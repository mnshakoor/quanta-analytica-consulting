Operational Sequence

How the Reader Works

01
Input

Upload an EPUB via drag-and-drop or file selector. The file is read into browser memory as an ArrayBuffer. Nothing leaves your device.

02
Extraction

JSZip opens the archive in memory. The parser resolves container.xml, finds the OPF package document, and reads the manifest and spine entries.

03
TOC Construction

Builds the table of contents from NCX (EPUB 2) or nav documents (EPUB 3), with spine-order fallback when no structured TOC is present.

04
Rendering

Chapter bodies are normalized, images resolved to local object URLs from the archive, and the full spine rendered into a scrollable reading surface.

05
Navigation

Click any TOC item to view that section and all child sections. All link resolution and navigation operate entirely client-side.

Frequently Asked

Technical Questions

Does this reader upload my files anywhere?

No. All processing occurs within your browser session. File data is held in local memory only and cleared when you close the tab.

Which EPUB versions are supported?

Both EPUB 2 (NCX-based TOC) and EPUB 3 (nav document TOC) are supported, with spine-order fallback when no structured TOC exists.

Does it work offline or on a local PC?

Yes. Double-click the HTML file to open it in any modern browser. Fonts load from Google on first use but EPUB processing works fully offline.

Can I host this on GitHub Pages?

Yes. Upload this single HTML file to your GitHub repository and enable GitHub Pages. No build steps or configuration required.

Are images inside the EPUB rendered?

Yes. Embedded images are resolved to temporary local object URLs from the archive. Remote resources are blocked for security.

Can I copy text from a chapter?

Yes. Click inside the reading panel and press Cmd/Ctrl + A to select only that chapter's content, then copy as normal.
